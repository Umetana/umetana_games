# 子ども向けノノグラム Webアプリ

## 新規制作向け実装仕様書 v0.3

## 1. 本書の目的

本書は、子どもがスマートフォンやタブレットで気軽に遊べる、10×10固定のノノグラムゲームを新規制作するための実装仕様書である。

本作は本格的なWebサービスや大規模なゲーム製品ではなく、短い待ち時間や暇なときに遊べる軽量なブラウザゲームとする。GitHub Pagesなどの静的ホスティングへ配置し、URLを開くだけで遊べることを目的とする。

## 2. 最優先の実装条件

以下は、他の要件より優先する。

- Vanilla HTML、CSS、JavaScriptのみで新規実装する
- React、Vue、Svelte、Next.jsなどのフレームワークを使用しない
- Vite、Webpackなどのビルドツールを使用しない
- TypeScriptを使用しない
- npm、Node.js、`package.json`、`node_modules`を必要としない
- サーバーサイド処理、データベース、API通信を実装しない
- Tailwind CSS、Font Awesome、Google Fontsなどの外部CDNを使用しない
- PWA化およびService Workerは初期版の対象外とする
- 静的ファイル一式を配置するだけで公開できる構成とする
- GitHub Pagesで公開可能な相対パス構成とする
- ページ読み込み後、ゲーム中に外部通信を行わない
- 過剰な抽象化、汎用フレームワーク化、将来機能の先行実装を行わない

開発時は単純な静的HTTPサーバーでの確認を基本とする。可能な範囲で `file://` による直接実行にも対応するが、ブラウザ固有の制約がある場合はGitHub Pages等のHTTP環境での動作を優先する。

## 3. 参考プロトタイプの扱い

別途添付するGemini製の「ノノグラム10x10」HTMLは、過去の別仕様に基づく参考プロトタイプであり、改修元ではない。

以下は参考または移植してよい。

- 10×10盤面の視覚表現
- 5マスごとの太い区切り線
- 行・列ヒントの算出方法
- 問題データ
- 問題選択画面の表現
- クリア演出および紙吹雪演出の考え方

一方、単一HTMLへの継ぎ足し、外部CDN、Mouse EventsとTouch Eventsの個別処理など、今回の仕様と異なる構成は継承しない。本書を優先し、新規に実装すること。

## 4. 対応環境

- スマートフォン
- タブレット
- PCブラウザ
- 縦画面を基本レイアウトとする
- 横画面でも操作不能にならず、大きく崩れない構成とする
- Chrome、Edge、Safariの現行版を主対象とする
- マウス、タッチ、ペン入力をPointer Eventsで統一して扱う
- キーボード操作は可能な範囲で対応するが、初期版の主操作にはしない

## 5. 画面構成

アプリは単一ページ内で画面を切り替えるSPA風の構成とする。ただし、フレームワークやURLルーターは使用しない。

### 5.1 タイトル画面

表示要素：

- ゲームタイトル
- 「はじめる」ボタン
- 「つづきから」ボタン
- 「おと設定」ボタン

「つづきから」は、最後に更新された有効な途中状態を再開する。途中状態がない場合は無効表示とする。問題ごとの途中状態には更新日時を持たせる。

### 5.2 問題選択画面

問題をカード形式で一覧表示する。

各カードの表示要素：

- ステージ番号
- 問題名
- 未クリアまたはクリア済み表示
- 完成画像の表示領域

未クリア問題では完成画像を「？」、仮表示、またはシルエットで隠す。クリア後は1:1のカラー完成画像を表示し、コレクションとして見返せるようにする。

### 5.3 ゲーム画面

表示要素：

- ステージ番号
- 問題名（未クリア時は「？？？」と伏せる）
- ミス回数
- おと設定ボタン
- 列ヒント
- 行ヒント
- 10×10盤面
- 「ぬる」モード
- 「×」モード
- 「けす」モード
- 「ひとつもどす」ボタン
- 「ヒント」ボタン
- 「さいしょから」ボタン
- 問題一覧へ戻るボタン

### 5.4 クリア画面

モーダルまたは画面内オーバーレイとして表示する。

表示要素：

- 「できた！」などの短いメッセージ
- 1:1カラー完成画像
- 問題名
- 「もういちど」ボタン
- 「つぎへ」ボタン
- 「もんだいをえらぶ」ボタン

最終問題をクリアした場合、「つぎへ」は問題一覧へ移動するか非表示とする。

## 6. ゲーム仕様

### 6.1 盤面

- 盤面サイズは10×10固定
- 上部に列ヒントを表示
- 左側に行ヒントを表示
- 問題ごとに10×10の正解データを持つ
- 行・列ヒントは正解データから自動生成する
- 初期収録は5問程度を目安とする
- 問題データの追加時にゲームロジックの変更を必要としない構成とする
- 5行目と6行目の間、5列目と6列目の間を太線で区切る

### 6.2 マスの状態

各マスは以下のいずれかの状態を持つ。

- 未入力
- 塗り
- ×

「けす」はマスを未入力へ戻す操作であり、独立した保存状態ではない。

### 6.3 入力モード

画面下部に以下の3モードを表示する。

- ぬる
- ×
- けす

選択中のモードは、背景色、枠、アイコン、文字などを併用して明確に示す。色だけに依存しない。

初期選択は「ぬる」とする。

### 6.4 タップ入力

- 「ぬる」で未入力または×のマスを操作すると、正解判定後に塗る
- 「×」で未入力または塗りのマスを操作すると、正解判定後に×を付ける
- 「けす」で塗りまたは×のマスを操作すると未入力へ戻す
- 「けす」ではミス判定を行わない
- 同一状態への入力は何も変更しない

### 6.5 スライド入力

- 指、マウス、ペンを押したまま滑らせて連続入力できる
- スライド開始時の入力モードを、指またはボタンを離すまで固定する
- 一回のスライド中、同じマスを重複処理しない
- 斜め移動を許可し、実際に通過したマスへ入力する
- 高速移動でPointer Eventsの通知間隔が空いた場合は、直前座標との間にある経路上のマスを補間して処理する
- 盤面操作中のみブラウザのスクロールを抑止する
- 盤面外の通常スクロールやページ拡大機能は必要以上に禁止しない
- スライド中にミスが発生した場合、そのマスを元へ戻し、そのスライド操作を終了扱いとする
- ミス後は指またはボタンを一度離し、再度操作すると入力を再開できる
- ミスより前に成立した変更は残し、その変更全体を一手として履歴へ記録する。成立した変更が0件なら履歴へ追加しない
- 押下中に盤面外へ出た場合はそのスライドを終了し、盤面へ戻っても指またはボタンを離すまで再開しない

### 6.6 即時正誤判定

子ども向けのため、塗りと×の両方を入力時に即判定する。

- 正解マスを塗る：正しい入力として残す
- 不正解マスを塗る：ミスとして元の状態へ戻す
- 不正解マスに×を付ける：正しい入力として残す
- 正解マスに×を付ける：ミスとして元の状態へ戻す
- 消す操作：判定しない

ミス時の挙動：

- 対象マスを短く揺らす
- 仮テキストとして「あっ」「おっと」などを短時間表示する
- 効果音が設定済みならミス音を鳴らす
- 音声素材が設定済みならミス音声を再生する
- 誤入力は保存せず、操作直前の状態へ戻す
- ミス回数を1増やす

ライフ、減点、ゲームオーバー、ステージ失敗は設けない。ミス回数は評価、クリア条件、報酬に影響しない。

連続再生を避けるため、ミス音声には短いクールダウンを設ける。目安は700～1000msとする。

### 6.7 ミス回数

- 現在のプレイにおけるミス回数を表示する
- 表示文言は威圧的にせず、「おっと！ 2かい」などの柔らかい表現を使用できる
- 途中状態と一緒に保存する
- 「さいしょから」および「もういちど」で0に戻す
- クリア済み記録にはミス回数を必要としない

### 6.8 行・列の完成

その行または列の正解マスがすべて正しく塗られた時点で完成扱いとする。空白マスをすべて×にする必要はない。

- 完成した行・列のヒントを薄くする、チェック表示を付けるなどして視覚的に示す
- 同じ行・列の初回完成時に短い完成演出を行う
- 一手で行と列が同時完成した場合、効果音は一度だけでよい
- 消去により未完成へ戻った後、再完成した場合は再度演出してよい
- 正解マスがない行・列のヒントは「0」と表示し、開始時から完成表示にする。ただし開始時の完成演出は行わない
- 行・列の完成状態は保存せず、盤面変更時および復元時に再計算する

### 6.9 クリア判定

すべての正解マスが塗られた時点でクリアとする。不正解の塗りは即時に戻されるため、盤面上には残らない。

クリア時の流れ：

1. 盤面操作を停止
2. 完成した盤面を短く光らせる
3. 盤面または完成形を短く拡大・バウンドさせる
4. 必要に応じて紙吹雪などの軽い演出を表示
5. 1:1カラー完成画像または仮表示を表示
6. クリア効果音・音声が設定済みなら再生
7. クリア画面の各ボタンを表示

クリア処理は一度だけ実行し、演出中やクリア後に重複実行しない。

## 7. 補助機能

### 7.1 一手戻す

- 直前の成立した操作を一手戻す
- タップ入力は1マスを一手とする
- スライド入力は押してから離すまでを一手とする
- スライドで変更した複数マスをまとめて戻す
- ミスで自動的に取り消された入力は履歴に残さない
- ヒントによる入力は一手として履歴に残す
- 戻した結果も自動保存する
- 初期版では「やり直す（Redo）」は実装しない
- 操作履歴は問題ごとに直近100手まで保存し、上限を超えた場合は古い履歴から削除する

### 7.2 ヒント

- 未入力の正解マスからランダムに1マス選んで塗る
- 正解マスに誤って×が残ることはないため、未入力マスのみ対象とする
- ヒント入力も通常どおり行・列完成およびクリア判定の対象とする
- ヒント入力は操作履歴へ一手として記録する
- 使用回数制限、減点、ペナルティは設けない
- 対象となる正解マスがない場合は使用不可とする

### 7.3 盤面リセット

- ボタン名は「さいしょから」など、全消去と分かる表現にする
- 実行前に画面内確認ダイアログを表示する
- 確認後、塗り、×、操作履歴、ミス回数を初期化する
- クリア済み情報とおと設定は消去しない
- キャンセルした場合は何も変更しない

## 8. スタート演出

問題開始時に短いスタート演出を行う。

- ステージ番号または問題名を表示
- 「はじめ！」「いくよー！」などの仮テキストを表示
- 音声素材が設定済みならスタート音声を再生
- 演出中は盤面操作を無効化
- 長いカウントダウンは設けない
- 演出時間は約0.5～1.2秒を目安とする

途中状態から再開する場合も短い演出を表示してよいが、毎回長く待たせない。

## 9. 音声・BGM・効果音

### 9.1 基本方針

画像、BGM、効果音、音声素材は別途用意し、後から追加する。初期実装時点で素材が未用意でもゲーム全体が正常に動作すること。

- 外部サイトから素材を取得しない
- AI等で仮画像や仮音声を自動生成しない
- 素材がない場合は無音および仮テキストで進行する
- 素材がないことをエラー扱いにしない
- 空の素材パスへアクセスして404を発生させない
- 素材追加後、設定または問題データの変更だけで反映できる構成とする

### 9.2 BGM

- 明るく軽い雰囲気を想定
- 30～60秒程度のループ素材を想定
- ゲーム中に控えめな音量で再生
- タイトル画面や問題選択画面での再生有無は実装時に統一する
- ブラウザの自動再生制限に従い、最初のユーザー操作後に再生を開始する
- 再生不可でもゲーム進行を止めない

### 9.3 効果音

追加可能な効果音：

- マス入力音
- 行または列の完成音
- ミス音
- クリア演出音
- ボタン操作音

### 9.4 音声

追加可能な短い音声：

- スタート音声：2種類程度
- ミス音声：3種類程度
- クリア音声：2種類程度

複数素材がある場合はランダム再生する。同じ音声が不自然に連続しないよう配慮する。

### 9.5 おと設定

以下を個別にON・OFFできるようにする。

- BGM
- 効果音
- 音声

- 初期値はすべてONとする
- ON・OFF変更を即時反映する
- 設定内容をLocalStorageへ保存する
- 初期版では音量スライダーを設けない
- 音がOFFでも、画面上の反応だけでゲームの状態を理解できるようにする

## 10. 完成画像

- 比率は1:1
- 推奨サイズは512×512px
- WebP形式を基本とする
- 子どもが見て分かりやすい題材とする
- 細かすぎる絵は避ける
- ノノグラムの完成形と印象が大きくずれないようにする
- 画像は後から追加する
- 画像未設定時は問題名、絵文字、単色背景などによる仮表示を使用する

初期問題候補：

- ねこ
- うさぎ
- さかな
- りんご
- ほし

参考プロトタイプに含まれる別の問題データを採用してもよい。正式な収録問題は実装開始前または素材追加時に確定する。

## 11. 問題データ仕様

問題データは専用JavaScriptファイル内の配列として管理する。JSONを `fetch()` する方式は、ローカル実行時の制約を避けるため初期版では使用しない。

例：

```js
const PUZZLES = [
  {
    id: "cat",
    revision: 1,
    stage: 1,
    name: "ねこ",
    placeholder: "🐱",
    image: "",
    solution: [
      "0011110000",
      "0110011000",
      "1100001100",
      "1001100100",
      "1011110100",
      "1010010100",
      "1000000100",
      "0100001000",
      "0011110000",
      "0000000000"
    ]
  }
];
```

要件：

- `id`は問題ごとに重複しない固定文字列とする
- `revision`は正解データ変更時に増やす正の整数とする
- `stage`は表示順を表す
- `name`は表示用の問題名とする
- `placeholder`は完成画像未設定時の仮表示に使用する
- `image`は完成画像の相対パスとし、未設定時は空文字とする
- `solution`は10文字×10行とし、`1`を正解マス、`0`を空白マスとする
- データ読み込み時に形式を簡易検証し、不正な問題はゲーム全体を停止させず一覧から除外する
- 行・列ヒントは`solution`から生成し、問題データへ重複保存しない

## 12. 保存仕様

LocalStorageを使用して以下を端末内へ保存する。

- 問題ごとの途中盤面
- 問題ごとのミス回数
- 問題ごとの操作履歴
- クリア済み問題ID
- BGM設定
- 効果音設定
- 音声設定
- 最後に遊んだ問題ID
- 保存データのバージョン
- 問題ごとの更新日時および問題リビジョン

保存タイミング：

- 正しいマス入力後
- 消去後
- 一手戻し後
- ヒント使用後
- ミス回数変更後
- 設定変更後
- 問題選択画面などへ移動する前

クリア成立時にクリア済みIDを保存し、その問題の途中盤面、ミス回数、操作履歴を削除する。クリア済み情報は保持する。「もういちど」またはクリア済み問題の再選択時に、新しい途中状態として保存できる。

保存データにはバージョン番号を持たせる。途中状態には問題の`revision`を保存し、不一致の場合はその問題の途中状態のみ破棄する。破損や形式不一致の場合もゲーム全体を利用不能にしない。

LocalStorageの読み書きは例外処理を行う。保存不能でも現在のセッションでは遊べるようにし、必要に応じて非致命的な案内を表示する。

アカウント登録、クラウド同期、個人情報収集は行わない。

## 13. UI・アクセシビリティ方針

- 子どもでも読める大きめの日本語を使用する
- 難しい漢字や長い説明を避ける
- ボタンは大きく押しやすくする
- アイコンと文字を併記する
- 色だけに依存せず、形、枠、ラベルでも状態を示す
- タップ可能領域は原則44px四方以上を目安とする
- 誤操作しやすいボタン同士は間隔を空ける
- リセット操作には確認表示を入れる
- ゲーム画面に広告、課金導線、外部リンクを置かない
- 音がなくても入力、ミス、完成、クリアが分かるようにする
- `user-scalable=no`でページ拡大を全面禁止しない
- 画面幅が広い場合は全体へ最大幅を設定し、盤面が過度に大きくならないようにする
- 小さい画面では盤面、ヒント、主要操作を優先し、装飾を簡略化する
- `prefers-reduced-motion: reduce`の場合は、揺れ、バウンド、紙吹雪などの動きを省略または短縮する
- 操作用ボタンは原則として`button`要素を使用し、Tab移動とEnter／Spaceによる実行を可能にする
- モーダル表示中は背後の要素を操作できないようにし、閉じた後は適切な要素へフォーカスを戻す
- 盤面の矢印キー操作は初期版の対象外とする

## 14. レイアウト方針

- アプリ全体の最大幅は600px程度を目安とする
- 盤面とヒントを利用可能な横幅へ収める
- 盤面の各マスは正方形とする
- マスの目標サイズは28px以上とするが、小型端末では全体が収まることを優先する
- 入力モード3種は盤面の直下へ配置する
- 「ひとつもどす」「ヒント」「さいしょから」は入力モードと視覚的に区別する
- ゲーム画面全体を一画面へ無理に押し込まず、必要に応じてページスクロールを許可する
- 盤面操作とページスクロールが競合しないよう、盤面部分に限定して適切な`touch-action`を設定する

## 15. 推奨ファイル構成

```text
/
├─ index.html
├─ css/
│  └─ style.css
├─ js/
│  ├─ puzzles.js
│  ├─ storage.js
│  ├─ audio.js
│  ├─ game.js
│  └─ app.js
└─ assets/
   ├─ images/
   └─ audio/
      ├─ bgm/
      ├─ se/
      └─ voice/
```

ファイル数は目安であり、小規模さを損なわない範囲で統合してよい。ただし、すべてを`index.html`へ埋め込む構成にはしない。

## 16. 初期版の対象外

- ランキング
- スコア競争
- 制限時間
- ライフ制

## 17. 初期実装の完成条件

以下をすべて満たした時点で、初期試作を完成とする。

- ビルド不要の静的HTML／CSS／JavaScriptとして動作する
- GitHub Pages相当の静的環境で起動できる
- 外部CDNや外部APIへ依存しない
- 10×10盤面が正しく表示される
- 5問程度を選択して遊べる
- 行・列ヒントが正解データから正しく生成される
- 「ぬる」「×」「けす」が動作する
- タップおよびスライド入力が動作する
- マウス、タッチ、ペンをPointer Eventsで扱う
- 塗りと×の即時正誤判定が動作する
- ミス入力が自動的に元へ戻る
- ミス回数が保存・復元される
- ミスによるゲームオーバーや進行不能がない
- 一手戻し、ヒント、リセットが動作する
- 正解マスがすべて塗られたとき、一度だけクリア処理が実行される
- 未クリア／クリア済みに応じて問題カードの表示が変わる
- 完成画像未設定時は仮表示で正常に進行する
- 音声・BGM・効果音未設定時でもエラーなく遊べる
- BGM、効果音、音声の個別ON・OFFが保存される
- 問題ごとの途中状態とクリア済み情報がLocalStorageへ保存される
- スマートフォン、タブレット、PCで操作可能である
- 横画面でも主要操作が利用可能である
- 通常操作でコンソールエラーを発生させない

## 18. 実装時の進め方

1. 静的ファイル構成と画面切り替えを作成
2. 問題データとヒント算出を実装
3. 盤面表示とPointer Events入力を実装
4. 即時判定、ミス処理、クリア判定を実装
5. 一手戻し、ヒント、リセットを実装
6. LocalStorage保存・復元を実装
7. 問題選択、クリア画面、仮テキスト演出を実装
8. スマートフォンとPCで操作確認
9. 後から画像・音声素材を追加できる受け口を確認

素材が未用意であることを理由に実装を停止しない。初期試作では仮テキスト、絵文字、単色背景、無音状態を用いてゲームロジックと操作性を完成させる。
